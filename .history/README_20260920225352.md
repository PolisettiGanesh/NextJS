# Next.js `<Image>` — Overall Cheat Sheet

The **`next/image`** component is Next.js's optimized replacement for the normal HTML `<img>` element.

---

## 1. Import

```jsx
import Image from "next/image";
```

---

# 2. Basic Image

```jsx
<Image
  src="/nextJS.jpg"
  width={500}
  height={300}
  alt="Next.js"
/>
```

If the image is inside:

```text
public/nextJS.jpg
```

use:

```jsx
src="/nextJS.jpg"
```

### Important

Don't write:

```jsx
src="/public/nextJS.jpg" ❌
```

or:

```jsx
import image from "/public/nextJS.jpg"; ❌
```

---

# 3. `public` Folder

If your structure is:

```text
public/
├── nextJS.jpg
├── images/
│   └── hero.jpg
└── products/
    └── phone.jpg
```

Use:

```jsx
<Image src="/nextJS.jpg" ... />
```

```jsx
<Image src="/images/hero.jpg" ... />
```

```jsx
<Image src="/products/phone.jpg" ... />
```

### Rule

```text
public/file.jpg
      ↓
/file.jpg
```

The `public` part disappears from the URL.

---

# 4. Static Local Import

You can also keep images outside `public` and import them.

Example:

```text
app/
└── (users)/
    ├── images/
    │   └── react.jpg
    └── page.js
```

Then:

```jsx
import Image from "next/image";
import ReactImage from "./images/react.jpg";
```

Use:

```jsx
<Image
  src={ReactImage}
  alt="React"
  width={200}
  height={150}
/>
```

With static imports, Next.js can automatically obtain image metadata such as dimensions.

---

# 5. `src`

There are two common forms.

### Public image

```jsx
<Image src="/nextJS.jpg" ... />
```

### Imported image

```jsx
<Image src={ReactImage} ... />
```

Notice the difference:

```jsx
src="/nextJS.jpg"    // string
```

versus:

```jsx
src={ReactImage}     // imported variable
```

---

# 6. `width` and `height`

Basic usage:

```jsx
<Image
  src="/nextJS.jpg"
  width={500}
  height={300}
  alt="Next.js"
/>
```

They define the image's intrinsic dimensions/aspect ratio and help Next.js reserve space to reduce **layout shift**.

They don't necessarily mean the image will always appear exactly `500 × 300` CSS pixels.

---

# 7. `alt`

Always provide appropriate alternative text.

```jsx
<Image
  src="/profile.jpg"
  width={200}
  height={200}
  alt="Profile photo"
/>
```

For a decorative image:

```jsx
<Image
  src="/decoration.png"
  width={100}
  height={100}
  alt=""
/>
```

### Avoid

```jsx
alt="image" ❌
```

Better:

```jsx
alt="Next.js logo" ✅
```

---

# 8. `fill`

Use `fill` when the image should fill its parent container.

```jsx
<div className="relative h-96">
  <Image
    src="/hero.jpg"
    alt="Hero"
    fill
    className="object-cover"
  />
</div>
```

### Important

The parent needs a suitable size/positioning context.

With Tailwind:

```jsx
<div className="relative h-96">
```

is a common pattern.

---

# 9. `object-cover`

```jsx
className="object-cover"
```

The image fills the container while maintaining its aspect ratio.

Some parts may be cropped.

```text
Container
┌──────────────────────┐
│    ┌────────────┐    │
│    │   IMAGE    │    │
│    │   CROPPED  │    │
│    └────────────┘    │
└──────────────────────┘
```

Good for:

* Hero images
* Banners
* Cover photos
* Cards

---

# 10. `object-contain`

```jsx
className="object-contain"
```

The entire image remains visible.

There may be empty space around it.

Good for:

* Product images
* Logos
* Shoes
* Phones
* Electronics

Example:

```jsx
<div className="relative h-64">
  <Image
    src="/phone.jpg"
    alt="Phone"
    fill
    className="object-contain"
  />
</div>
```

---

# 11. `sizes`

Very important when using responsive images, especially with `fill`.

Example:

```jsx
<Image
  src="/hero.jpg"
  alt="Hero"
  fill
  sizes="100vw"
  className="object-cover"
/>
```

For a layout where the image takes half the screen on desktop:

```jsx
sizes="(max-width: 768px) 100vw, 50vw"
```

Meaning:

```text
Mobile       → 100% viewport width
Desktop      → 50% viewport width
```

### Remember

> `sizes` tells the browser approximately how much space the image will occupy.

---

# 12. Responsive Image

Example:

```jsx
<div className="relative h-80 w-full">
  <Image
    src="/hero.jpg"
    alt="Hero"
    fill
    sizes="100vw"
    className="object-cover"
  />
</div>
```

This is a common production pattern.

---

# 13. Flexbox + Images

If you want multiple images next to each other and you're using Tailwind:

```jsx
<div className="flex gap-4">
  <Image
    src="/nextJS.jpg"
    alt="Next.js"
    width={200}
    height={150}
  />

  <Image
    src={ReactImage}
    alt="React"
    width={200}
    height={150}
  />
</div>
```

### Tailwind

```jsx
flex
```

### Bootstrap

```jsx
d-flex
```

Don't confuse them.

---

# 14. Remote Images

You can use an external image:

```jsx
<Image
  src="https://example.com/image.jpg"
  width={800}
  height={600}
  alt="Example"
/>
```

But remote image sources need to be configured in `next.config.ts`.

For example:

```ts
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "example.com",
      },
    ],
  },
};

export default nextConfig;
```

The exact configuration should match the remote host you trust.

---

# 15. Image Optimization

One major reason to use:

```jsx
import Image from "next/image";
```

instead of:

```jsx
<img src="/hero.jpg" />
```

is that Next.js can optimize images.

Benefits include things such as:

* Appropriate image sizing
* Responsive image delivery
* Lazy loading where appropriate
* Modern image formats when supported
* Layout-shift protection
* Better loading performance

---

# 16. `<img>` vs `<Image>`

### HTML

```jsx
<img
  src="/hero.jpg"
  alt="Hero"
/>
```

### Next.js

```jsx
<Image
  src="/hero.jpg"
  width={1200}
  height={600}
  alt="Hero"
/>
```

For most application images in Next.js, prefer `Image` when its optimization features are useful.

---

# 17. `fill` vs `width` + `height`

### Fixed/intrinsic image

Use:

```jsx
<Image
  src="/photo.jpg"
  width={800}
  height={600}
  alt="Photo"
/>
```

Good when you know the image's dimensions/aspect ratio.

### Container-based image

Use:

```jsx
<div className="relative h-96">
  <Image
    src="/photo.jpg"
    fill
    alt="Photo"
    className="object-cover"
  />
</div>
```

Good for:

* Hero sections
* Cards
* Background-like visual areas
* Responsive containers

# 18. Common Mistakes

### ❌ Mistake 1

```jsx
src="/public/nextJS.jpg"
```

### ✅ Correct

```jsx
src="/nextJS.jpg"
```

---

### ❌ Mistake 2

Trying to import from `public`:

```jsx
import image from "/public/nextJS.jpg";
```

### ✅ Correct

```jsx
<Image src="/nextJS.jpg" ... />
```

---

### ❌ Mistake 3

Using `fill` without a properly sized parent.

```jsx
<div>
  <Image fill src="/hero.jpg" alt="Hero" />
</div>
```

### ✅ Better

```jsx
<div className="relative h-96">
  <Image
    fill
    src="/hero.jpg"
    alt="Hero"
    className="object-cover"
  />
</div>
```

---

### ❌ Mistake 4

Using responsive/fill images without thinking about `sizes`.

```jsx
<Image fill src="/hero.jpg" alt="Hero" />
```

### ✅ Better

```jsx
<Image
  fill
  src="/hero.jpg"
  alt="Hero"
  sizes="100vw"
  className="object-cover"
/>
```

---

### ❌ Mistake 5

Bad accessibility:

```jsx
alt="image"
```

### ✅ Better

```jsx
alt="Developer working on a laptop"
```

# 🧠 Interview Cheat Sheet

### What is `next/image`?

> `next/image` is Next.js's image component that provides image optimization, responsive sizing, lazy loading where appropriate, and layout-shift protection.

### How do you use an image from `public`?

```jsx
<Image src="/image.jpg" ... />
```

Not:

```jsx
<Image src="/public/image.jpg" ... />
```

### Can you import images?

Yes. Static local images can be imported:

```jsx
import hero from "./images/hero.jpg";
```

then:

```jsx
<Image src={hero} alt="Hero" />
```

### What is `fill`?

`fill` makes the image fill its positioned parent container.

### Why use `sizes`?

It tells the browser how much space the responsive image is expected to occupy so it can choose an appropriate image resource.

### Why is `alt` important?

It provides alternative text for accessibility and when the image cannot be displayed.

### `object-cover` vs `object-contain`?

```text
object-cover
→ fills container
→ may crop image

object-contain
→ entire image visible
→ may leave empty space
```
